## English

### 1. Project Stage

The RC helium balloon blimp project has moved from basic two-motor testing to Bluetooth remote-control testing.

Before this update, the project mainly verified whether the ESP32-C3 SuperMini could drive two 720 coreless motors through the DRV8833 motor driver. Today, the firmware and wiring plan were updated so the motors can be controlled by the Dabble mobile app GamePad module.

The goal of this stage is to make the blimp easier to control before real flight testing. Instead of only running a fixed motor test sequence, the operator can now send live control commands from a phone.

### 2. Completed Hardware Wiring Plan

#### 2.1 Power Center and Main Switch

The battery is connected through a 3-pin slide switch before powering the breadboard rail. This gives the system a simple main power switch.

| Connection | Destination | Purpose |
| --- | --- | --- |
| Battery black wire / negative | Breadboard blue GND rail | Main ground line |
| Battery red wire / positive | Center pin of the 3-pin slide switch | Power input to switch |
| Slide switch output pin | Breadboard red VCC rail | Switched power output |

After this wiring, the breadboard red rail is treated as the main `VCC`, and the blue rail is treated as the main `GND`.

#### 2.2 ESP32-C3 SuperMini Power

| ESP32-C3 SuperMini | Destination | Note |
| --- | --- | --- |
| 5V | Breadboard red VCC rail | Main power input for the ESP32-C3 |
| GND | Breadboard blue GND rail | Shared ground |

Important note: the ESP32-C3 is connected through the `5V` pin in this wiring plan. The main power rail must not be connected to the `3V3` pin.

#### 2.3 DRV8833 Motor Driver and Enable Line

| DRV8833 Pin | Destination | Purpose |
| --- | --- | --- |
| VCC | Breadboard red VCC rail | Power input for motor driver |
| GND | Breadboard blue GND rail | Shared ground |
| EEP | Breadboard red VCC rail | Enable / wake line |

The `EEP` pin is required. If this pin is not connected to VCC, the DRV8833 can remain disabled and the motors may not move even when the control signals are correct.

#### 2.4 Capacitor Protection

| Component | Placement | Polarity | Purpose |
| --- | --- | --- | --- |
| 100uF electrolytic capacitor | Near the DRV8833 power rail | Long leg to VCC, short leg / stripe side to GND | Helps stabilize power during motor startup |
| 104 ceramic capacitor | Across the left motor terminals | No polarity | Reduces motor electrical noise |
| 104 ceramic capacitor | Across the right motor terminals | No polarity | Reduces motor electrical noise |

The 100uF capacitor is placed near the DRV8833 because the motors can draw sudden current when starting. The capacitor helps reduce voltage drops. The 104 ceramic capacitors are soldered directly across the motor terminals to reduce motor noise.

#### 2.5 Signal Wiring

| ESP32-C3 GPIO | DRV8833 Input | Firmware Constant | Function |
| --- | --- | --- | --- |
| GPIO4 | IN1 | `IN1` | Left motor forward control |
| GPIO5 | IN2 | `IN2` | Left motor backward control |
| GPIO6 | IN3 | `IN3` | Right motor forward control |
| GPIO7 | IN4 | `IN4` | Right motor backward control |

#### 2.6 Motor Output

| Motor | DRV8833 Output |
| --- | --- |
| Left 720 coreless motor | OUT1 and OUT2 |
| Right 720 coreless motor | OUT3 and OUT4 |

If a motor direction is reversed during testing, the two output wires of that motor can be swapped.

### 4. Firmware Changes

#### 4.1 Dabble GamePad Control

The firmware now uses the Dabble ESP32 library and only enables the GamePad module:

```cpp
#define CUSTOM_SETTINGS
#define INCLUDE_GAMEPAD_MODULE

```

The Bluetooth device name was updated to:


This is the name that should appear in the Dabble app when connecting from the phone.

#### 4.2 Motor Pin Definitions

The motor control pins are:

```cpp
const int IN1 = 4;
const int IN2 = 5;
const int IN3 = 6;
const int IN4 = 7;
```

These match the ESP32-C3 to DRV8833 signal wiring.

#### 4.3 Speed Settings

The current speed settings are:

```cpp
const int CRUISE_SPEED = 255;
const int TURN_FAST_SPEED = 255;
const int TURN_SLOW_SPEED = 120;
```

`CRUISE_SPEED` is used for straight movement. `TURN_FAST_SPEED` is used by the outside motor while turning. `TURN_SLOW_SPEED` is used by the inside motor while turning.

The current values are intentionally strong for testing motor response. These values may need to be reduced after the motors are installed on the actual blimp frame.

#### 4.4 Smooth Acceleration

The firmware now tracks actual motor output speed:

```cpp
int currentLeftSpeed = 0;
int currentRightSpeed = 0;
```

The ramp value is:

```cpp
const int RAMP_SPEED = 15;
```

Instead of instantly jumping to the target speed, the `drive()` function gradually increases or decreases the motor speed. This reduces sudden current draw and helps prevent power drop or ESP32-C3 reset when the motors start.

#### 4.5 Motor Output Function

The `setMotor()` function receives a speed value from `-255` to `255`.

- Positive speed: motor turns forward.
- Negative speed: motor turns backward.
- Zero speed: motor stops.

This makes the motor control easier to read because forward and backward movement can be represented by the sign of the speed value.

### 5. Control Logic

The `handleGamePad()` function reads the Dabble GamePad buttons:

```cpp
bool up = GamePad.isUpPressed();
bool down = GamePad.isDownPressed();
bool left = GamePad.isLeftPressed();
bool right = GamePad.isRightPressed();
```

Then it calculates target speed for the left and right motors.

| Dabble Input | Left Motor Target | Right Motor Target | Result |
| --- | --- | --- | --- |
| Up | `CRUISE_SPEED` | `CRUISE_SPEED` | Straight forward |
| Down | `-CRUISE_SPEED` | `-CRUISE_SPEED` | Straight backward |
| Left | `TURN_SLOW_SPEED` | `TURN_FAST_SPEED` | Wide left turn |
| Right | `TURN_FAST_SPEED` | `TURN_SLOW_SPEED` | Wide right turn |
| Up + Left | `TURN_SLOW_SPEED` | `TURN_FAST_SPEED` | Forward left arc |
| Up + Right | `TURN_FAST_SPEED` | `TURN_SLOW_SPEED` | Forward right arc |
| Down + Left | `-TURN_SLOW_SPEED` | `-TURN_FAST_SPEED` | Backward left arc |
| Down + Right | `-TURN_FAST_SPEED` | `-TURN_SLOW_SPEED` | Backward right arc |
| No button | `0` | `0` | Smooth stop |

The single left and right buttons do not perform sharp in-place rotation. Instead, both motors keep moving forward, but one side is slower. This creates a smoother and wider turning radius, which is more suitable for a helium blimp.

### 7. Testing Plan

Recommended test sequence:

1. Confirm all power is off.
2. Check the battery negative line is connected to the GND rail.
3. Check the battery positive line enters the slide switch first.
4. Check the slide switch output goes to the VCC rail.
5. Check ESP32-C3 `5V` and `GND`.
6. Check DRV8833 `VCC`, `GND`, and `EEP`.
7. Check GPIO4 to IN1, GPIO5 to IN2, GPIO6 to IN3, and GPIO7 to IN4.
8. Check 100uF capacitor polarity.
9. Check both 104 capacitors on the motors.
10. Upload the firmware.
11. Open Dabble and connect to `Innovation_Balloon`.
12. Test each direction without propellers.
13. Confirm forward, backward, left arc, and right arc.
14. If a direction is wrong, fix motor wiring or adjust firmware direction.

### 8. Problems to Watch For

| Problem | Possible Cause | Fix |
| --- | --- | --- |
| Motors do not move | DRV8833 `EEP` is not connected | Connect `EEP` to VCC |
| ESP32-C3 restarts when motors start | Voltage drop from motor startup current | Check battery, capacitor, and reduce speed/ramp settings |
| One motor direction is reversed | Motor output wires are reversed | Swap the two output wires of that motor |
| Left and right controls are reversed | Motor sides or output direction are reversed | Swap motor connections or adjust code |
| Dabble cannot connect | Bluetooth name not found or ESP32 not powered | Check power and search for `Innovation_Balloon` |
| Motor noise affects control | Capacitors missing or wiring too loose | Recheck 104 capacitors and common ground |

### 1. 專案階段

RC 氦氣飛船專案今天從「雙馬達基本測試」進入「藍牙遙控測試」階段。

前一階段主要確認 ESP32-C3 SuperMini 是否能透過 DRV8833 馬達驅動模組控制兩顆 720 空心杯馬達。今天的重點是把固定測試流程改成手機即時遙控，讓操作者可以透過 Dabble App 的 GamePad 模組控制飛船前進、後退與轉向。

這個階段的目標是讓飛船在實際飛行測試前，先具備比較穩定、可重複操作的遙控能力。

### 2. 今日完成的硬體接線規劃

#### 2.1 能源中心與總開關

電池會先進入 3 腳滑動開關，再由開關輸出到麵包板電源軌。這樣整個系統就有一個主電源開關。

| 接線 | 接到 | 目的 |
| --- | --- | --- |
| 電池黑線 / 負極 | 麵包板藍色總地線軌 GND | 系統共同地線 |
| 電池紅線 / 正極 | 3 腳滑動開關的正中間腳位 | 開關電源輸入 |
| 滑動開關左邊或右邊輸出腳 | 麵包板紅色總電源軌 VCC | 開關後的系統電源 |

完成後，麵包板紅色軌視為整個系統的 `VCC`，藍色軌視為整個系統的 `GND`。

#### 2.2 ESP32-C3 SuperMini 供電

| ESP32-C3 SuperMini | 接到 | 說明 |
| --- | --- | --- |
| 5V | 麵包板紅色總電源軌 VCC | 目前接線使用的供電腳 |
| GND | 麵包板藍色總地線軌 GND | 與馬達驅動共地 |

重要注意：目前接法是把電源接到 ESP32-C3 的 `5V` 腳位，絕對不能把主電源軌接到 `3V3` 腳位。

#### 2.3 DRV8833 馬達驅動與喚醒線

| DRV8833 腳位 | 接到 | 目的 |
| --- | --- | --- |
| VCC | 麵包板紅色總電源軌 VCC | 馬達驅動電源 |
| GND | 麵包板藍色總地線軌 GND | 系統共同地線 |
| EEP | 麵包板紅色總電源軌 VCC | 啟用 / 喚醒 DRV8833 |

`EEP` 是非常重要的喚醒線。若沒有接到 VCC，DRV8833 可能會維持關閉狀態，即使 ESP32-C3 有送控制訊號，馬達也不會動。

#### 2.4 電容防護

| 元件 | 位置 | 正負極 | 作用 |
| --- | --- | --- | --- |
| 100uF 電解電容 | 靠近 DRV8833 的 VCC 與 GND 電源軌之間 | 長腳接 VCC，短腳 / 白條紋側接 GND | 穩定馬達啟動時的電源 |
| 104 陶瓷電容 | 左馬達兩個接點之間 | 不分正負極 | 降低馬達雜訊 |
| 104 陶瓷電容 | 右馬達兩個接點之間 | 不分正負極 | 降低馬達雜訊 |

720 空心杯馬達啟動時可能會產生瞬間電流變化與電氣雜訊。100uF 電解電容用來幫助穩定供電，104 陶瓷電容則用來降低馬達端產生的雜訊。

#### 2.5 訊號線

| ESP32-C3 GPIO | DRV8833 輸入 | 程式常數 | 功能 |
| --- | --- | --- | --- |
| GPIO4 | IN1 | `IN1` | 左馬達前進控制 |
| GPIO5 | IN2 | `IN2` | 左馬達後退控制 |
| GPIO6 | IN3 | `IN3` | 右馬達前進控制 |
| GPIO7 | IN4 | `IN4` | 右馬達後退控制 |

#### 2.6 動力輸出

| 馬達 | DRV8833 輸出 |
| --- | --- |
| 左 720 空心杯馬達 | OUT1 與 OUT2 |
| 右 720 空心杯馬達 | OUT3 與 OUT4 |

如果測試時某一顆馬達方向相反，可以直接對調該馬達接在 DRV8833 輸出的兩條線。

### 4. 程式更新內容

#### 4.1 加入 Dabble GamePad 藍牙遙控

程式使用 Dabble ESP32 函式庫，並只啟用 GamePad 模組：

```cpp
#define CUSTOM_SETTINGS
#define INCLUDE_GAMEPAD_MODULE
#include <DabbleESP32.h>
```

藍牙裝置名稱設定為：

```cpp
Dabble.begin("Innovation_Balloon");
```

手機 Dabble App 連線時，應該尋找 `Innovation_Balloon` 這個名稱。

#### 4.2 馬達腳位定義

目前程式使用的馬達控制腳位如下：

```cpp
const int IN1 = 4;
const int IN2 = 5;
const int IN3 = 6;
const int IN4 = 7;
```

這四個腳位對應到 ESP32-C3 與 DRV8833 的訊號接線。

#### 4.3 速度參數

目前速度設定如下：

```cpp
const int CRUISE_SPEED = 255;
const int TURN_FAST_SPEED = 255;
const int TURN_SLOW_SPEED = 120;
```

`CRUISE_SPEED` 用於直線前進或後退。`TURN_FAST_SPEED` 是轉彎時外側馬達的速度。`TURN_SLOW_SPEED` 是轉彎時內側馬達的速度。

目前數值偏向測試最大推力與馬達反應。實際裝上飛船後，可能需要依照飛船重量、浮力、螺旋槳方向與電池狀態再調整。

#### 4.4 新增軟啟動與平滑加減速

程式新增兩個變數，用來記錄目前實際輸出的馬達速度：

```cpp
int currentLeftSpeed = 0;
int currentRightSpeed = 0;
```

加減速步進值設定為：

```cpp
const int RAMP_SPEED = 15;
```

馬達不會從 `0` 瞬間跳到 `255`，而是每次 loop 慢慢靠近目標速度。這樣可以降低啟動瞬間電流，讓 ESP32-C3 比較不容易因為電壓下降而重啟或斷電。

#### 4.5 馬達輸出函式

`setMotor()` 使用 `-255` 到 `255` 的速度值控制馬達：

- 正數代表正轉。
- 負數代表反轉。
- `0` 代表停止。

這樣設計後，前進與後退可以用速度的正負號表示，程式邏輯會比較清楚。

### 5. 遙控邏輯

`handleGamePad()` 會讀取 Dabble GamePad 的四個方向鍵：

```cpp
bool up = GamePad.isUpPressed();
bool down = GamePad.isDownPressed();
bool left = GamePad.isLeftPressed();
bool right = GamePad.isRightPressed();
```

接著依照按鍵組合計算左右馬達的目標速度。

| Dabble 輸入 | 左馬達目標 | 右馬達目標 | 飛船動作 |
| --- | --- | --- | --- |
| 上 | `CRUISE_SPEED` | `CRUISE_SPEED` | 直線前進 |
| 下 | `-CRUISE_SPEED` | `-CRUISE_SPEED` | 直線後退 |
| 左 | `TURN_SLOW_SPEED` | `TURN_FAST_SPEED` | 大半徑左轉 |
| 右 | `TURN_FAST_SPEED` | `TURN_SLOW_SPEED` | 大半徑右轉 |
| 上 + 左 | `TURN_SLOW_SPEED` | `TURN_FAST_SPEED` | 前進左弧線 |
| 上 + 右 | `TURN_FAST_SPEED` | `TURN_SLOW_SPEED` | 前進右弧線 |
| 下 + 左 | `-TURN_SLOW_SPEED` | `-TURN_FAST_SPEED` | 後退左弧線 |
| 下 + 右 | `-TURN_FAST_SPEED` | `-TURN_SLOW_SPEED` | 後退右弧線 |
| 無按鍵 | `0` | `0` | 平滑減速停止 |

單獨按左或右時，程式不是讓馬達原地反轉，而是讓左右兩顆馬達都往前轉，只是內側馬達較慢。這樣會形成比較自然的大半徑轉彎，比較適合氦氣飛船這種慣性較大、轉向不適合太急的載具。

### 8. 可能遇到的問題

| 問題 | 可能原因 | 解決方式 |
| --- | --- | --- |
| 馬達完全不動 | DRV8833 `EEP` 沒有接到 VCC | 將 `EEP` 接到紅色 VCC 電源軌 |
| ESP32-C3 一啟動馬達就重啟 | 馬達啟動電流造成電壓下降 | 檢查電池、100uF 電容，或降低速度 / 調小加速幅度 |
